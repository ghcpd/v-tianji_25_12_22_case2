### 1) Fix missing cleanup of global event listeners (bugfix) 🔧
- **Why**: In App.tsx an effect adds `resize` and `click` listeners but never removes them — this can cause memory leaks or duplicate handlers during re-renders. Small, well-scoped change with clear testable behavior.
- **Clarifying questions**
  - Should we keep these listeners on the whole app or scope them to a specific element/component?
  - Do you want us to extract handlers into `useCallback` for stability?
  - Any specific browser support constraints?
- **High‑level approach**
  - Add a cleanup function to the `useEffect` that removes the handlers when the component unmounts.
  - Optionally move handlers to `useCallback` so identity is stable.
  - Test manually by opening/closing the component (or via unit tests that mount/unmount) and confirm only one listener exists.

---

### 2) Add resilient `localStorage` handling (defensive improvement) 🛡
- **Why**: `JSON.parse` of `localStorage.getItem('todos')` can throw if the stored data is corrupted or not valid JSON. A small change with low risk and immediate reliability benefit.
- **Clarifying questions**
  - Do we want to clear invalid data, or fall back to an empty array and notify the user?
  - Is there a preference to migrate/backup bad data?
- **High‑level approach**
  - Wrap `JSON.parse` in try/catch. On error, set todos to `[]` and optionally remove the invalid `todos` key or save a backup under a different key.
  - Add a unit test asserting corrupted JSON results in empty state and doesn't crash.

---

### 3) Replace deprecated `onKeyPress` with `onKeyDown` and improve keyboard handling (accessibility/compatibility) ⌨️
- **Why**: `onKeyPress` is deprecated in modern React and may behave inconsistently. Small behavioral change that improves accessibility.
- **Clarifying questions**
  - Should Enter also trigger when composing IME input (i.e., how to handle IME)? 
  - Any existing keyboard shortcuts to preserve?
- **High‑level approach**
  - Switch the input from `onKeyPress` to `onKeyDown`, handle `e.key === 'Enter'`.
  - Add tests (unit or integration) to confirm pressing Enter adds a todo.
  - Manual test for IME if needed.

### 4) Improve accessibility (labels, ARIA attributes, and focus state) ♿
- **Why**: Many controls (input, checkboxes, filter buttons, delete button) lack explicit accessible labels/attributes. These are easy-to-scope enhancements that improve inclusivity.
- **Clarifying questions**
  - Preference for aria labels vs visible labels? (e.g., a live region vs labels)
  - Should we prioritize WCAG level or minimal ARIA changes?
- **High‑level approach**
  - Add `aria-label` to the text input (e.g., `aria-label="Add todo"`).
  - Add `aria-pressed` or `aria-current` to filter buttons; mark active one with `aria-pressed="true"`.
  - Add `aria-label` to the Delete button (e.g., `aria-label="Delete todo: {text}"`).
  - Ensure focus outlines/states are visible in CSS.
  - Add a small accessibility-focused test (e.g., using @testing-library/jest-dom to assert `aria-*` attributes).
